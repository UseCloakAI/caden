# Caden

Multi-device home voice agent. Static web app (no build) + Android WebView wrapper. See README.md for the architecture.

- Web app files ship as-is: `index.html`, `css/`, `js/`, `icons/`, `manifest.webmanifest`, `sw.js`. The Android app bundles the same files (`android/app/build.gradle` `syncWeb`) — new top-level web files must be added there, to `SHELL` in `sw.js`, and to the Pages stage step in `.github/workflows/ship.yml`.
- Bump `CACHE` in `sw.js` when shipping changes to shell files.
- Design: Ribbon (UseCloakAI/ribbon): sky gradient (`.sky-day`/`.sky-night`, `html.night` by time of day or dark mode), Geist (self-hosted in `fonts/`), frosted glass (`--card` + `backdrop-filter`), one blue accent (`--acc`; `--on-acc` on fills). Caden is the wave (`js/wave.js`, canvas `#wave`): one ribbon living in a band along the bottom (`--wave-h`, ~30% of the screen); words, menus and the clock never sit on it. `#orb` is an invisible tap/drag target over that band. The only header control is the options button (`#btnOptions`), which drops the options list (`js/wheel.js`, still called the wheel: a glass list with a spring highlight; slide, scroll, arrows, hand swipe, tap/pinch). The rooms bar (`#rooms`) is the one bottom control: a pill per screen, Caden's filled; tapping one sends Caden there (`sendTo`, non-holders ask the holder with a `sendto` mesh message). After 45 s idle, `html.resting` moves the clock to the middle, large: the clock is drawn once at 200px and moved by transform only (`placeClock`), never by layout properties, so the tween stays smooth. Old header controls stay as hidden elements because code still updates them. Icons are Phosphor (`icons/ph`); no emoji, no hand-drawn SVG icons. No em-dashes or middot chains in UI copy.
- Brain = Caden Supabase project (`wiimiqqmdmfikuqgqhtm`) edge function `brain`; model = Cloak `/v1/chat` `model:"kairos"` (NVIDIA Nemotron first). Caden uses Cloak's general endpoints (`/v1/chat` kairos, `/v1/speech`) but no Caden-specific code lives in the Cloak repo; keep it that way. Background/utility work must not use chat tiers.
- Touch-free display mode (`html.display`, `settings.display`, `#display`): hand tracking. `js/hands.js` turns MediaPipe Gesture Recognizer output into a pointer (index knuckle, so pinching doesn't move it), pinch state and gestures (wave / swipe / thumbs up / thumbs down / fist rests); its `analyze(hands, t)` is pure and unit-testable. `js/airnav.js` owns the cursor, pinch-to-press (on release, so a drag cancels it), pinch-drag scroll and the hand preview. Air targets exclude external links and downloads (a kiosk must not navigate away). Faces and hands share `js/camera.js`; never open a second `getUserMedia`. `?debug` exposes `window.__caden` for tests.
- Voice: Cloak API `POST /v1/speech` (NVIDIA Magpie TTS Multilingual on Cloak's key pool; `GET /v1/speech/voices`). `Mouth` prefetches per sentence and must always fall back to the device voice on any error.
- Voice location (`js/locate.js`): wake-word loudness minus this device's calibration, shared as `heard` mesh messages; loudest wins after `ARB_MS`. Never use AGC on the meter stream. A device that's alone must act immediately.
- Waking (`android/.../CadenService.java`): once in a home the APK runs a quiet foreground service (special-use) with a partial wake lock so the WebView stays connected while asleep (`CadenNative.keepAlive`, `settings.wakeHere`; the activity skips `web.onPause()` then). When Caden is handed to a hidden page, `wakeForArrival` calls `CadenNative.wake()` (bright wake lock + direct start + full-screen-intent notification; the activity shows over the lock screen and turns the screen on) and waits for `visibilitychange` before the arrival plays. Android needs the user's OK for full-screen intents (API 34+) and/or Display over other apps; Settings' Waking card links to those pages (`wakeStatus` / `openWakeSettings`).
- APK updates (`android/.../Updater.java`): web builds come from Pages `version.json` (per-file SHA-256, verified, swapped atomically into `files/www`, applied when JS says Caden is idle); native updates only when the `native` source hash changes and both builds are stable-signed (CI secrets). `app.json` in the APK and `version.json` on Pages share `github.run_number` as the build number. Never serve a web file that failed its hash.
- Sounds (`js/sfx.js`): smart-speaker character, warm and deep, never toy-like: `tone()` voices (sine + soft 2nd/3rd harmonics + a sub, low-passed under ~2.5 kHz, gentle attacks), mostly G2 to G4 in G major, a dark warm room; offline-rendered, per-sound peak targets. Caden's moment names map to palette sounds through `ALIAS`. `select` (two deep notes gliding up) means "listening". Wheel: `tick` per step (lower when turning back), `bump` at an end, `enter`/`back` open/close, `select` to choose. No bright FM bells, kalimba plucks or high clicks.
- Join QR (`js/qr.js`): encodes `PUBLIC_URL#join=<code>` (never `location.origin`: the APK serves from caden.app). It's the home key: hidden until asked, auto-hides after 2 min.
- Mesh payloads are always encrypted (`js/mesh.js`); never send plaintext over Realtime, and never send camera frames anywhere.
- LAN links (`js/lan.js`): one WebRTC data channel per device, signaled through the mesh as `rtc` messages (consumed inside the mesh, never dispatched). Routing in `Mesh.send`: links first; relay when a known device has no open link, the packet is over `MAX_DC`, or the type is in `RELAY_ALWAYS` (`hello`/`beat`/`bye`/`rtc`, so new devices are found). Messages are deduped by id, so double delivery is fine. `lan.known` tracks every device heard from; a dropped link must never make messages to that device disappear.
- The holder protocol (claim / handoff / epoch) is in `js/app.js` — keep "highest epoch wins, ties to lower id".
- Brain tools (in the `brain` edge function): live weather from Open-Meteo (free, no key; coarse coords from `js/where.js`: device location only if already granted, else get.geojs.io IP lookup, named by BigDataCloud's free client geocoder), and web search through Cloak's general `/v1/search`. Time-sensitive questions (`NEEDS_WEB`) are searched up front as keywords (`webQuery`); the model can also ask with a `<search q="..."/>` reply (the brain holds the first characters to catch it, max 2 rounds). Actions are `DO:` lines, never spoken (format in `HOME_NOTE`): `go`, `tell <room> | msg` (Caden flies there and says it: handoff carries `line`), `announce <where> | msg` (mesh `announce`, chime + notice + the device's own voice), `timer` / `alarm <when> | label | <where>`, `cancel`, `dim`, `volume`, `clock`, `continue`. `runActions` resolves screens (`resolveWhere`: everywhere / here / room lists) and returns notes; `nextStep` gives the model a `[System]` turn with those notes when it asked to continue or something failed (max `MAX_STEPS` in a row), which is how it works like an agent. Which screens a timer goes on is the model's call (it asks when it's unclear); never hardcode that. `go`/`dim`/`volume`/`clock` only run when recent human words asked for that kind of thing (`ASKED`); a reply that is only actions speaks its notes. Moves and announcements wait until Caden finishes talking (`later`).
- Timers and alarms (`js/clocks.js` parsing; state in `app.js`): every device keeps the home's full list (mesh `clock` set / stop / all-on-hello, saved per home), only the screens in `where` ring. Ringtones `ring` / `alarm` (and the `announce` chime) play with `force` even when sound effects are off, swell over 45 s, stop after 10 min; Stop (button, Esc, or saying stop) stops it on every screen; alarms can snooze 5 min. Countdown pills sit under the clock.
- Caden's wave follows the real speech: `speechTrack` (js/voice.js) decodes each Magpie clip into a 10 ms loudness envelope and brightness (zero-crossing) curve; `Mouth.speech()` reads them at the playback position. The device voice has no audio to read, so it falls back to word pulses.
- Replies are spoken: the playbook is `HOME_NOTE`, in two copies that must stay identical: `supabase/functions/brain/index.ts` and `js/config.js` (direct-to-Cloak fallback).
- Motion (Ribbon: premium and calm): `--e-out` decelerate in, `--e-in` accelerate out, durations 180 / 420 / 900 ms. The wheel uses Ribbon's orbit spring (k 200, c 25), velocity trail and rubber-banded ends. The wave's flights retract strands toward the side Caden leaves by and sweep them back in from the side it arrives from. Long replies scroll in place (`setWide` is a no-op layout now).
- Quality (`settings.quality`: auto / low / medium / high, Settings > Display slider; `html[data-quality]` is the level in effect): motion is identical at every level, only drawing cost changes. `QUALITY` in `js/wave.js` sets the wave's dpr cap, strands, curve samples, sparks and fps cap (low: 30 fps); low drops every `backdrop-filter` for near-opaque glass, medium softens it. Auto starts from `guessQuality()` (device memory / cores) and steps down when the wave's draw cost averages over 7 ms. The wave canvas only covers its band, and stops drawing while the page is hidden. Don't add a new animation that only looks right on high.
- Respect `prefers-reduced-motion` (the wave slows almost to still and flights become a dim, the wheel snaps without springing, CSS durations collapse).
