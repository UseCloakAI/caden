# Caden

Multi-device home voice agent. Static web app (no build) + Android WebView wrapper. See README.md for the architecture.

- Web app files ship as-is: `index.html`, `css/`, `js/`, `icons/`, `manifest.webmanifest`, `sw.js`. The Android app bundles the same files (`android/app/build.gradle` `syncWeb`) — new top-level web files must be added there, to `SHELL` in `sw.js`, and to the Pages stage step in `.github/workflows/ship.yml`.
- Bump `CACHE` in `sw.js` when shipping changes to shell files.
- Design: Frutiger Aero over Ribbon's structure, kept calm (not corny). Background (`.aero` in index.html): a soft sky gradient, a faint glow top right, a fine wireframe globe (`js/globe.js`: orthographic lat / long lines on a canvas sized to the globe's box only, dpr ≤ 1.5, near side brighter, lower right, about three minutes a turn at ~15 fps, static on low quality / reduced motion) and the wave's own drifting dust (its sparks). No bubbles, hills, clouds, aurora or stars. Gloss is deliberate and limited: primary buttons, selected chips, the menu highlight and the options orb are glossy aqua (white shine on the top half), secondary buttons are glossy silver glass, overlays (options list, Settings) are Vista-style glass with a top sheen. Low quality and reduced motion keep the look but stop the bubbles, cloud drift and aurora. Ribbon (UseCloakAI/ribbon) underneath: sky gradient (`.sky-day`/`.sky-night`; `html.night` from `settings.theme`: auto = 7pm to 7am or the device's dark mode, or forced light / dark from Settings > Display), Geist (self-hosted in `fonts/`), frosted glass (`--card` + `backdrop-filter`), one blue accent (`--acc`; `--on-acc` on fills). Caden is the wave (`js/wave.js`, canvas `#wave`): one ribbon living in a band along the bottom (`--wave-h`, ~30% of the screen); words, menus and the clock never sit on it. `#orb` is an invisible tap/drag target over that band. The only header control is the options button (`#btnOptions`), which drops the options list (`js/wheel.js`, still called the wheel: a glass list with a spring highlight; slide, scroll, arrows, hand swipe, tap/pinch). The rooms bar (`#rooms`) is the one bottom control: a pill per screen, Caden's filled; tapping one sends Caden there (`sendTo`, non-holders ask the holder with a `sendto` mesh message). Tapping the clock toggles resting (`toggleRest`; the header passes taps through so the clock is tappable). Lock (`DO: lock`, options > Lock screen, `html.locked`): dimmer to 0.9, a faint light clock, native brightness 0.02; it unlocks on a touch or key, the wake word, an arrival, a ringing timer or an announcement, or motion (`js/motion.js`: the shared camera at 48x36 grayscale, frame differencing, on device only; camera released on unlock). After 45 s idle, `html.resting` moves the clock to the middle, large (everything else steps back, including the away card on screens Caden isn't on): the clock is drawn once at 200px and moved by transform only (`placeClock`), never by layout properties, so the tween stays smooth. Old header controls stay as hidden elements because code still updates them. Icons are Phosphor (`icons/ph`); no emoji, no hand-drawn SVG icons. Avoid the "AI UI" tells: blurred glass only on true overlays (options list, Settings sheet, nothing smaller; Aero gloss on buttons is a painted sheen, not backdrop blur), one small radius (`--pill` is 10px; only toggle switches are round), no glow orbs or decorative gradients beyond the sky, no drop shadows except overlays, Settings as flat sections with hairlines (never cards inside a card), controls as text where they can be (the rooms bar is words with a rule under the current room), and plain copy (no "Tip:", no arrow paths like Settings → People). No em-dashes or middot chains in UI copy.
- Brain = Caden Supabase project (`wiimiqqmdmfikuqgqhtm`) edge function `brain`; model = Cloak `/v1/chat` `model:"pneuma"` (fast; kairos reasoning was too slow for voice, and the coming Kairos Fast / Smart split is still a large model, so it stays a fallback); the brain tries pneuma twice, then `FALLBACK` (kairos, linus), and skips a tier that sends no words within `FIRST_WORD_MS` (6 s, by the clock, since keep-alives arrive while a model thinks). Caden uses Cloak's general endpoints (`/v1/chat`, `/v1/speech`) but no Caden-specific code lives in the Cloak repo; keep it that way. Background/utility work must not use chat tiers.
- Touch-free display mode (`html.display`, `settings.display`, `#display`): hand tracking. `js/hands.js` turns MediaPipe Gesture Recognizer output into a pointer (index knuckle, so pinching doesn't move it), pinch state and gestures (wave / swipe / thumbs up / thumbs down / fist rests); its `analyze(hands, t)` is pure and unit-testable. `js/airnav.js` owns the cursor, pinch-to-press (on release, so a drag cancels it), pinch-drag scroll and the hand preview. Air targets exclude external links and downloads (a kiosk must not navigate away). Faces and hands share `js/camera.js`; never open a second `getUserMedia`. `?debug` exposes `window.__caden` for tests.
- Voice: Cloak API `POST /v1/speech` (NVIDIA Magpie TTS Multilingual on Cloak's key pool; `GET /v1/speech/voices`). Send one `lang` (the voice list holds a comma list; NVIDIA rejects it), and a 4xx never trips the 60 s voice lockout. `Mouth` prefetches per sentence and must always fall back to the device voice on any error.
- Voice location (`js/locate.js`): wake-word loudness minus this device's calibration, shared as `heard` mesh messages; loudest wins after `ARB_MS`. Never use AGC on the meter stream. A device that's alone must act immediately.
- Waking (`android/.../CadenService.java`): once in a home the APK runs a quiet foreground service (special-use) with a partial wake lock so the WebView stays connected while asleep (`CadenNative.keepAlive`, `settings.wakeHere`; the activity skips `web.onPause()` then). When Caden is handed to a hidden page, `wakeForArrival` calls `CadenNative.wake()` (bright wake lock + direct start + full-screen-intent notification; the activity shows over the lock screen and turns the screen on) and waits for `visibilitychange` before the arrival plays. Android needs the user's OK for full-screen intents (API 34+) and/or Display over other apps; Settings' Waking card links to those pages (`wakeStatus` / `openWakeSettings`).
- APK window (`MainActivity.immersive`): full screen, edge to edge, no status / navigation bar (a swipe shows them briefly), drawn into the display cutout, window and WebView background the night sky (never white). `CadenNative.setBrightness(level)` sets the window brightness (below 0 hands it back to the system).
- APK updates (`android/.../Updater.java`): web builds come from Pages `version.json` (per-file SHA-256, verified, swapped atomically into `files/www`, applied when JS says Caden is idle); native updates only when the `native` source hash changes and both builds are stable-signed (CI secrets). `app.json` in the APK and `version.json` on Pages share `github.run_number` as the build number. Never serve a web file that failed its hash.
- Sounds (`js/sfx.js`): smart-speaker character, warm and deep, never toy-like: `tone()` voices (sine + soft 2nd/3rd harmonics + a sub, low-passed under ~2.5 kHz, gentle attacks), mostly G2 to G4 in G major, a dark warm room; offline-rendered, per-sound peak targets. Caden's moment names map to palette sounds through `ALIAS`. `select` (two deep notes gliding up) means "listening". Wheel: `tick` per step (lower when turning back), `bump` at an end, `enter`/`back` open/close, `select` to choose. No bright FM bells, kalimba plucks or high clicks.
- Join QR (`js/qr.js`): encodes `PUBLIC_URL#join=<code>` (never `location.origin`: the APK serves from caden.app). It's the home key: hidden until asked, auto-hides after 2 min.
- Mesh payloads are always encrypted (`js/mesh.js`); never send plaintext over Realtime, and never send camera frames over the mesh or anywhere else. The one exception is vision: when the model replies `DO: look`, `camera.still()` takes a single JPEG (768 px) and it rides only on the next brain turn (`images`, passed to Cloak's vision models, never stored), with a "Looking" notice on screen. Never stream, store or send stills otherwise.
- LAN links (`js/lan.js`): one WebRTC data channel per device, signaled through the mesh as `rtc` messages (consumed inside the mesh, never dispatched). Routing in `Mesh.send`: links first; relay when a known device has no open link, the packet is over `MAX_DC`, or the type is in `RELAY_ALWAYS` (`hello`/`beat`/`bye`/`rtc`, so new devices are found). Messages are deduped by id, so double delivery is fine. `lan.known` tracks every device heard from; a dropped link must never make messages to that device disappear.
- The holder protocol (claim / handoff / epoch) is in `js/app.js` — keep "highest epoch wins, ties to lower id".
- Smart stack: the fast tier (pneuma) routes every turn by the playbook's HOW TO ANSWER block (answer / search / look / agent / DO line; right beats quick, never guess). `DO: agent <task>` (`runActions` → `nextStep` → a `[System]` turn with `agent`) runs `orchestrate` in the brain: Cloak `kairos` (Smart, then `kairos-fast`) plans in rounds (`ORCHESTRATOR`, max `AGENT_ROUNDS`, `AGENT_MS`), fans out `<search q/>` and `<bot task/>` helpers in parallel (`HELPER`: pneuma, then kairos-fast, max `MAX_BOTS`), and ends with a `<report>` that lands in the system prompt as AGENT REPORT; the fast tier then says it. Never route ordinary turns to Smart.
- Brain tools (in the `brain` edge function): live weather from Open-Meteo (free, no key; coarse coords from `js/where.js`: device location only if already granted, else get.geojs.io IP lookup, named by BigDataCloud's free client geocoder), and web search through Cloak's general `/v1/search`. Time-sensitive questions (`NEEDS_WEB`) are searched up front as keywords (`webQuery`); the model can also ask with a `<search q="..."/>` reply (the brain holds the first characters to catch it, max 2 rounds). Actions are `DO:` lines, never spoken; `splitActions` puts an inline `DO:` / `REMEMBER:` on its own line before anything reads a reply and `speakable` cuts a sentence there, and the brain keeps DO lines in stored history (`keep`) so the model sees its actions in the right format (format in `HOME_NOTE`): `go`, `tell <room> | msg` (Caden flies there and says it: handoff carries `line`), `announce <where> | msg` (mesh `announce`: a three-tone cabin-PA chime, the notice, then the device's own voice; when the request mentions announcing, Caden holds its own words and drops them if the announcement plays on this screen), `timer` / `alarm <when> | label | <where>`, `cancel`, `dim`, `volume`, `clock`, `continue`. `runActions` resolves screens (`resolveWhere`: everywhere / here / room lists) and returns notes; `nextStep` gives the model a `[System]` turn with those notes when it asked to continue or something failed (max `MAX_STEPS` in a row), which is how it works like an agent. Which screens a timer goes on is the model's call (it asks when it's unclear); never hardcode that. `go`/`dim`/`volume`/`clock` only run when recent human words asked for that kind of thing (`ASKED`); a reply that is only actions speaks its notes. Moves and announcements wait until Caden finishes talking (`later`).
- Timers and alarms (`js/clocks.js` parsing; state in `app.js`): every device keeps the home's full list (mesh `clock` set / stop / all-on-hello, saved per home), only the screens in `where` ring. Ringtones `ring` / `alarm` (and the `announce` chime) play with `force` even when sound effects are off, swell over 45 s, stop after 10 min; Stop (button, Esc, or saying stop) stops it on every screen; alarms can snooze 5 min. Countdown pills sit under the clock, placed from the clock's measured box (`placeClock` sets `--clocks-top`; while resting they form a row under the date and the clock shrinks to fit above the wave), and are updated in place, never rebuilt per second. Saying stop / dismiss / snooze stops every clock that's due anywhere, from whichever screen heard it. Alerts (ringtones, announce chime) have their own volume (`settings.alertVol`, `sfx.alertBus`, Settings > Voice).
- The wave's moods (`MOOD` in js/wave.js: speed, amplitude, brightness, spread, twist, shimmer, breathe, lean) give each state its own body; strands are drawn as smooth midpoint curves that drift slightly against each other, a shimmer gradient runs along them, high quality adds a soft glow core, and each syllable onset sends a ripple outward from the middle.
- Caden's wave follows the real speech: `speechTrack` (js/voice.js) decodes each Magpie clip into a 10 ms loudness envelope and brightness (zero-crossing) curve; `Mouth.speech()` reads them at the playback position. The device voice has no audio to read, so it falls back to word pulses.
- Listening etiquette: a turn heard during follow-up listening (no wake word, `followUpOpen`) is marked in HOME CONTEXT (`overheard`, plus `asked` when Caden's last reply was a question); the model replies `DO: ignore` to speech that wasn't for it (silent, back to idle) and `DO: done` when the conversation is over (stops listening). Which is which is the model's call, from the playbook; don't hardcode it.
- Speech text (`js/spoken.js`): `Mouth.say` runs every line through `spoken()` so times, temperatures, units, money, dates and ranges are said the way a person says them ("9:05 AM" → "nine oh five A M", "61°F" → "sixty one degrees"). Captions keep the written form. Add cases there, not in prompts.
- Replies are spoken: the playbook is `HOME_NOTE`, in two copies that must stay identical: `supabase/functions/brain/index.ts` and `js/config.js` (direct-to-Cloak fallback).
- Motion (Ribbon: premium and calm): `--e-out` decelerate in, `--e-in` accelerate out, durations 180 / 420 / 900 ms. The wheel uses Ribbon's orbit spring (k 200, c 25), velocity trail and rubber-banded ends. The wave's flights retract strands toward the side Caden leaves by and sweep them back in from the side it arrives from. Caden's words sit in the space between the top bar and the wave, from the left margin, starting large and shrunk by `fitWords()` (a measured binary search, at most once per frame, shrink-only within a reply so a new sentence usually costs one measurement) to the largest size that fits above the wave; words land with opacity + translate only (never a filter: per-word blur made replies stutter on tablets); the hint hides while words show (`html.talking-words`); past the floor they scroll in place (`setWide` is a no-op layout now). Toasts sit just above the rooms bar. The corner clock re-measures when fonts load and keeps clear of the right safe area.
- Quality (`settings.quality`: auto / low / medium / high, Settings > Display slider; `html[data-quality]` is the level in effect): motion is identical at every level, only drawing cost changes. `QUALITY` in `js/wave.js` sets the wave's dpr cap, strands, curve samples, sparks and fps cap (low: 30 fps); low drops every `backdrop-filter` for near-opaque glass, medium softens it. Auto starts from `guessQuality()` (device memory / cores) and steps down when the wave's draw cost averages over 7 ms. The wave canvas only covers its band, and stops drawing while the page is hidden. Don't add a new animation that only looks right on high.
- Respect `prefers-reduced-motion` (the wave slows almost to still and flights become a dim, the wheel snaps without springing, CSS durations collapse).
